## 2. パッケージ構成と責務

### 2.1 `cmd/main.go`
- **役割**: アプリケーション起動のエントリーポイント
- **処理**:
  - DBファイルの初期化
  - ルーターのセットアップ
  - HTTPサーバー起動（デフォルトポート: 8080）

### 2.2 `handler/`
- **役割**: HTTPリクエスト/レスポンスの処理
- **特徴**: Go初心者向け実装パターン
  ```go
  // パッケージ内の関数は「gin.Context」を受け取る
  // ctx.JSON(statusCode, responseData) でレスポンス
  // ctx.BindJSON(request) でリクエストボディをパース
  ```
- **モジュール**:
  - `fare_evidence.go`: 区間登録（ウィザード各ステップ、確認、登録）
  - `trips.go`: 利用実績の追加・編集・削除
  - `calendar.go`: カレンダー表示（月別trips集計）
  - `invoice.go`: 請求書作成・ダウンロード

### 2.3 `service/`
- **役割**: ビジネスロジック（バリデーション、集計、PDF生成指示）
- **特徴**: DBアクセスは`repository/`に委譲
  ```go
  // service は repository インターフェースに依存
  // テスト時は mock を挿入可能にする設計
  ```
- **モジュール**:
  - `fare_service.go`: 区間ロジック
  - `trip_service.go`: 利用実績ロジック
  - `invoice_service.go`: 請求書生成ロジック

### 2.4 `repository/`
- **役割**: SQLiteへのデータアクセス抽象化
- **特徴**: 
  - `interface.go`: インターフェース定義（service が依存）
  - `sqlite.go`: SQLiteを使った実装
  - テスト用 mock 実装も可能
- **モジュール**:
  - `FareRepository`: fare_evidence操作
  - `TripRepository`: trips操作
  - `InvoiceRepository`: invoices操作

### 2.5 `db/`
- **役割**: DB接続・マイグレーション・テーブル定義
- **モジュール**:
  - `db.go`: SQLite接続、初期化
  - `schema.sql`: DDL（CREATE TABLE等）
  - `migration.go`: バージョン管理・スキーマ更新（必要に応じて）

### 2.6 `pdf/`
- **役割**: PDF生成
- **実装フロー**:
  1. service から請求書データ（trips集計結果）受け取り
  2. Markdown形式の請求書テンプレート組み立て
  3. HTMLに変換（md2html ライブラリ）
  4. HTMLから PDF生成（wkhtmltopdf または Go純粋ライブラリ）
  5. バイナリを返す
- **モジュール**:
  - `generator.go`: PDF生成エンジン
  - `template.go`: Markdownテンプレート管理

### 2.7 `models/`
- **役割**: Goの構造体定義（DB行と1:1対応が基本）
- **モジュール**:
  - `fare_evidence.go`: FareEvidence構造体
  - `trips.go`: Trip構造体
  - `invoices.go`: Invoice構造体
  - `request.go`: HTTPリクエスト用DTO
  - `response.go`: HTTPレスポンス用DTO

### 2.8 `middleware/`
- **役割**: CORS、エラーハンドリング、ロギング
- **特徴**: gin の middleware 機能を活用

### 2.9 `config/`
- **役割**: 環境変数・設定値管理
- **例**:
  - DB ファイルパス（デフォルト: `/data/commute2invoice.db`）
  - サーバーポート（デフォルト: `8080`）
  - ログレベル

## 3. Go実装の基本パターン

### 3.1 構造体とメソッド

```go
// models/fare_evidence.go の例
type FareEvidence struct {
    ID           int
    Label        string
    CompanyText  string
    FromText     string
    ToText       string
    FareOneway   int
    FareRoundtrip *int  // NULLの場合は nil
    ImageMime    string
    ValidFrom    string
    ValidUntil   *string
    CreatedAt    string
}

// メソッド例: 往復運賃を計算
func (f *FareEvidence) GetRoundtripFare() int {
    if f.FareRoundtrip != nil {
        return *f.FareRoundtrip
    }
    return f.FareOneway * 2
}
```

### 3.2 インターフェース

```go
// repository/interfaces.go の例
type FareRepository interface {
    CreateFareEvidence(ctx context.Context, fare *models.FareEvidence) (int, error)
    GetFareEvidenceByID(ctx context.Context, id int) (*models.FareEvidence, error)
    ListValidFareEvidence(ctx context.Context, date string) ([]*models.FareEvidence, error)
}

// service は インターフェースに依存する（実装に依存しない）
type FareService struct {
    repo repository.FareRepository
}

func NewFareService(repo repository.FareRepository) *FareService {
    return &FareService{repo: repo}
}
```

### 3.3 エラーハンドリング

```go
// Go は戻り値として (結果, エラー) を返す慣例
func (s *FareService) CreateFare(ctx context.Context, fare *models.FareEvidence) (int, error) {
    // バリデーション
    if fare.FareOneway <= 0 {
        return 0, fmt.Errorf("invalid fare amount: %d", fare.FareOneway)
    }
    
    // DBアクセス
    id, err := s.repo.CreateFareEvidence(ctx, fare)
    if err != nil {
        return 0, fmt.Errorf("failed to create fare evidence: %w", err)
    }
    
    return id, nil
}
```

### 3.4 context の役割

```go
// HTTPリクエスト処理時、gin.Context がルーターから渡される
func (h *FareHandler) CreateFare(c *gin.Context) {
    var req CreateFareRequest
    if err := c.BindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }
    
    // gin.Context をそのまま service に渡す（キャンセル・タイムアウト処理に使われる）
    id, err := h.service.CreateFare(c.Request.Context(), req.ToModel())
    if err != nil {
        c.JSON(http.StatusInternalServerError, gin.H{"error": err.Error()})
        return
    }
    
    c.JSON(http.StatusCreated, gin.H{"id": id})
}
```

## 4. DB操作パターン

### 4.1 SQLite接続と初期化

```go
// db/db.go の構成
package db

import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"  // ドライバー登録
)

func InitDB(dbPath string) (*sql.DB, error) {
    // DBファイル（ディレクトリが無ければ作成）を開く
    db, err := sql.Open("sqlite3", dbPath)
    if err != nil {
        return nil, err
    }
    
    // テーブルが無ければ作成
    if err := migrateSchema(db); err != nil {
        return nil, err
    }
    
    return db, nil
}
```

### 4.2 INSERT パターン

```go
// repository/sqlite.go の例
func (r *SQLiteRepository) CreateFareEvidence(ctx context.Context, fare *models.FareEvidence) (int, error) {
    query := `
        INSERT INTO fare_evidence 
        (label, company_text, from_text, to_text, fare_oneway, fare_roundtrip, image, image_mime, valid_from, valid_until)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
    `
    
    result, err := r.db.ExecContext(ctx, query,
        fare.Label,
        fare.CompanyText,
        fare.FromText,
        fare.ToText,
        fare.FareOneway,
        fare.FareRoundtrip,
        fare.Image,  // BLOB はそのままバイナリ
        fare.ImageMime,
        fare.ValidFrom,
        fare.ValidUntil,
    )
    
    if err != nil {
        return 0, err
    }
    
    id, err := result.LastInsertRowid()
    return int(id), err
}
```

### 4.3 SELECT パターン

```go
// 複数行取得の例
func (r *SQLiteRepository) ListTrips(ctx context.Context, date string) ([]*models.Trip, error) {
    query := `
        SELECT id, date, fare_evidence_id, round_trip, billing_target, created_at
        FROM trips
        WHERE date = ?
        ORDER BY created_at
    `
    
    rows, err := r.db.QueryContext(ctx, query, date)
    if err != nil {
        return nil, err
    }
    defer rows.Close()
    
    var trips []*models.Trip
    for rows.Next() {
        trip := &models.Trip{}
        if err := rows.Scan(
            &trip.ID,
            &trip.Date,
            &trip.FareEvidenceID,
            &trip.RoundTrip,
            &trip.BillingTarget,
            &trip.CreatedAt,
        ); err != nil {
            return nil, err
        }
        trips = append(trips, trip)
    }
    
    return trips, rows.Err()
}
```

## 7. エラーハンドリング方針

### 7.1 HTTP ステータスコード
- `400 Bad Request`: リクエスト形式エラー、バリデーション失敗
- `404 Not Found`: リソース不在
- `409 Conflict`: 重複登録、請求書上書き時の確認待ち
- `500 Internal Server Error`: DB接続失敗、PDF生成失敗等

### 7.2 エラーレスポンス形式
```json
{
  "error": "エラーメッセージ",
  "code": "ERROR_CODE",
  "details": {...}
}
```
